# アプリ内ログイン

初回はAPIとPostgreSQLを起動した後、端末で次を実行し、最初の管理者のログインID・表示名・パスワードを設定する。パスワードは画面に表示されず、12文字以上を使用する。

```sh
docker compose -f infra/docker-compose.yml exec api python -m ai_interviewer_api.auth.bootstrap
```

ユーザーが既に存在する場合、このコマンドは初期管理者を作成しない。管理者はログイン後、ユーザーメニューの「システム設定」でユーザーの登録・編集・削除を行う。削除後も過去の記録と監査履歴は保持され、当該ユーザーのセッションは無効になる。パスワード、ログインID、ロールの変更時も当該ユーザーは再ログインする。

管理者がログインできなくなった場合、サーバーとデータベースへ操作権限を持つ担当者が次を端末で実行する。表示された有効な管理者からログインIDを入力し、新しいパスワードを2回入力する。復旧後はその管理者の既存セッションが無効になり、操作は監査ログに記録される。接続元に対するログイン回数制限は復旧後も最大15分間残る。

```sh
docker compose -f infra/docker-compose.yml exec api python -m ai_interviewer_api.auth.recover_admin
```

ログイン時に発行するセッションは12時間で期限切れとなる。パスワードはscryptで保存し、セッショントークンはサーバー側にハッシュで保存する。ログインの失敗はアカウントと接続元ごとに制限する。旧開発トークンによるログインは使用できない。

システム設定の操作履歴では、保存済みのユーザー登録・編集・削除・端末復旧を日時、操作主体、対象、操作結果、更新項目とともに確認できる。操作時点の表示名は新しい記録から保存する。以前の記録には現在の表示名を使用する。ログイン試行、失敗操作、更新前後の値は含まれず、ユーザーの更新と監査ログ保存は同一トランザクションではない。保持期間や改ざん検知など、正式な監査要件は別途整備する。

ローカル以外ではHTTPSを使用し、APIとVoiceの`APP_ENV`を`local`以外に設定する。公開する画面の正確なオリジンを`AUTH_ALLOWED_ORIGINS`にカンマ区切りで設定する。CookieにはSecure属性が設定される。リバースプロキシを使用する場合は接続元IPの扱いを環境に合わせて構成する。

既存のデモ記録には旧開発ユーザーIDが残る。新しい管理者は同一テナントの記録を閲覧できるが、新しい一般ユーザーに旧IDの記録が自動で割り当てられることはない。
