# 音声インタビュー評価テストケース

## 01. 一般インタビュー

### 目的

一般的なインタビューにおいて、以下の観点を音声E2Eで評価する。

- 正常回答の理解
- 部分回答・曖昧回答への深掘り
- 質問が分からない場合の言い換え
- 答えが思いつかない場合の支援
- フィラー・相槌・考え中の判定
- 既回答の再質問防止
- 訂正・否定・混在確認の処理
- 複数項目を一度に回答した場合の処理
- 拒否・スキップ・脱線への対応
- STT誤認識と意味的非回答の分離

## Criticalテスト

以下は重大な会話破綻につながるため、1件でも誤った場合はCritical Failとする。

### GEN-012: 既回答

**ユーザー発話**

> さっき開発って答えました

**禁止事項**

- 同じ質問を再度聞く
- 新しいquestionIdで同一内容を再生成する

**期待動作**

- 過去回答を参照する
- 必要なら既回答内容を起点に深掘りする

---

### GEN-014: 混在確認

**ユーザー発話**

> ちょっと違うけど、まあいいです

**禁止事項**

- CONFIRMEDにする
- 単純なCONFIRMATIONとして処理する

**期待動作**

- 訂正・留保を優先して解釈する
- どこが違うか確認する

---

### GEN-005: 質問が分からない

**ユーザー発話**

> どういう意味ですか？

**禁止事項**

- 「聞き取れませんでした」と返す
- STT_ERRORとして扱う

**期待動作**

- 質問を言い換える
- 必要なら具体例を提示する

---

### GEN-006: 答えが思いつかない

**ユーザー発話**

> よく分からないですね

**禁止事項**

- STT_ERRORとして扱う
- 同じ質問をそのまま繰り返す

**期待動作**

- 具体例を提示する
- 別角度から質問する
- 繰り返して答えられない場合はスキップ可能にする

---

### GEN-009: フィラー

**ユーザー発話**

> うーん

**禁止事項**

- 新しいquestionIdを発行する
- 新しい質問として再生成する

**期待動作**

- FieldStateを変更しない
- questionIdを維持する
- 自然な短い促しのみ返す

---

### GEN-017: 言い直し

**ユーザー発話**

> 31歳、いや32歳です

**禁止事項**

- 31歳を確定する

**期待動作**

- 言い直し後の32歳を採用する

---

### GEN-025: 回答拒否

**ユーザー発話**

> それは答えたくないです

**禁止事項**

- 同じ質問を繰り返す
- 回答を強要する

**期待動作**

- REFUSALとして受理する
- スキップまたは次項目へ進む

## 音声E2E評価データ形式

各ケースは、最終的に以下のような構造で機械評価できるようにする。

```yaml
id: GEN-014
category: general_interview

audio:
  text: "ちょっと違うけど、まあいいです"
  variation: normal

context:
  question: "強みはアプリ開発という理解でよいですか？"
  current_field: strengths
  current_state: AWAITING_CONFIRMATION

expected:
  dialogue_act:
    allow:
      - CORRECTION
      - QUALIFIED_CONFIRMATION

  field_state:
    must_not_be:
      - CONFIRMED

  question_id:
    behavior: KEEP_OR_CORRECTION_FLOW

  response:
    intent:
      - ASK_DIFFERENCE
      - CLARIFY_CORRECTION

forbidden:
  dialogue_act:
    - CONFIRMATION

  response_contains:
    - "聞き取れませんでした"

critical: true
```

## 評価指標案

### 会話精度

- Conversation Success Rate: 95%以上
- Critical Error Rate: 0〜1%以下
- Dialogue Act Accuracy: 95%以上
- FieldState Transition Accuracy: 98%以上

### 音声認識

- Transcript意味一致率
- 固有名詞認識率
- 数値認識率
- 訂正表現の最終値採用率
- STT不確実性と意味的非回答の誤分類率

### レイテンシ

- STT Final → 次質問表示
  - p50: 1.5秒以内を目標
  - p95: 3.0秒以内を目標
- STT Final → 音声再生開始
  - p95: 4.0秒以内を目標

# 02. システム開発・要件定義インタビュー

## 目的

システム開発・要件定義インタビューにおいて、単に利用者の発話を記録するだけでなく、以下を正しく整理・深掘りできるかを評価する。

- 現行業務と課題の把握
- 要求と解決策の分離
- 機能要件の具体化
- 非機能要件の具体化
- 業務ルール・例外条件の抽出
- ユーザー・権限の整理
- データ入出力・保存要件の整理
- 外部システム連携の整理
- 曖昧・矛盾・不足した回答への適切な深掘り
- 複数要件を一度に話した場合の分解
- 前回答の訂正・追加への追従
- 利用者が実装方式を要件として話した場合の目的確認

---

## Criticalテスト

以下は要件品質を大きく損なうため、原則1件でも誤った場合はCritical Failとする。

### SYS-002: 解決策を目的として確定しない

**質問**

> どのような課題を解決したいですか？

**ユーザー発話**

> Reactで画面を作りたいです

**禁止事項**

- 「Reactを使用する」をそのまま業務要求として確定
- 課題を聞かず次の項目へ進む

**期待動作**

- なぜReactが必要なのか確認する
- 本来解決したい業務課題を取得する

---

### SYS-014: 未決の境界値を勝手に補完しない

**質問**

> 10万円の場合はどちらの承認になりますか？

**ユーザー発話**

> そこ決めてないですね

**禁止事項**

- 10万円以上・以下のどちらかを推測で確定
- 質問を聞き取れなかった扱いにする

**期待動作**

- 未決事項として記録
- 必要であれば後で決定する項目として残す

---

### SYS-015: 矛盾をそのまま確定しない

**ユーザー発話**

> はい、でも申請者本人しか削除できません

**禁止事項**

- 最初の「はい」だけを拾って「誰でも削除可能」と確定

**期待動作**

- 後半の制約を優先して解釈
- 必要なら確認する

---

### SYS-018: 既回答の再質問禁止

**ユーザー発話**

> さっき課長って言いました

**禁止事項**

- 同じ質問を再生成
- 新しいquestionIdで同じ内容を聞く

**期待動作**

- 過去回答を参照
- 必要なら承認条件など未取得項目のみ深掘り

### SYS-028: 実装指定を無条件に要件確定しない

**期待動作**

## 構造化評価項目

システム開発インタビューでは、会話の自然さだけではなく、抽出された要件の構造も評価する。

### 必須評価対象

- business_goal
- current_process
- pain_point
- actor / role
- functional_requirement
- business_rule
- exception_rule
- input_data
- output_data
- authorization
- integration
- non_functional_requirement
- constraint
- priority
- unresolved_item
- assumption
- correction

### 例

```yaml
id: SYS-013
category: system_requirements

audio:
  text: "10万円未満は課長、それ以上は部長です"

context:
  question: "申請金額によって承認者は変わりますか？"

expected:
  dialogue_act:
    allow:
      - ANSWER

  extracted_requirements:
    - type: BUSINESS_RULE
      condition: "amount < 100000"
      action: "manager_approval"

    - type: BUSINESS_RULE
      condition: "amount >= 100000"
      action: "department_head_approval"

  field_state:
    expected: CONFIRMED

forbidden:
  - lose_numeric_threshold
  - merge_two_approval_rules
  - ask_same_question_again

critical: true
```

## 要件定義インタビュー固有の評価指標

### 要件抽出精度

- Requirement Extraction Accuracy: 95%以上
- Business Rule Extraction Accuracy: 98%以上
- Exception Rule Recall: 95%以上
- Numeric / Threshold Accuracy: 99%以上
- Correction Application Accuracy: 99%以上

### 会話制御

- 同一質問の不要な再質問率: 1%未満
- 曖昧回答への適切な深掘り率: 95%以上
- 解決策先行発話から目的へ戻せる率: 95%以上
- 未決事項を推測で確定する率: 0%
- 矛盾検知率: 95%以上
- 「質問が分からない」とSTT失敗の誤分類率: 1%未満

### Critical Error

以下はCritical Errorとして集計する。

- 未決事項を勝手に確定
- 数値・閾値を誤って保存
- 訂正前の値を確定
- 留保・否定を無視してCONFIRMED
- 既回答の同一質問を繰り返す
- 解決策をユーザー目的として誤登録
- 例外条件を落として基本ルールだけを保存
